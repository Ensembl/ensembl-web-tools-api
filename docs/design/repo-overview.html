The API seam

  • Two reads, both in the backend: form_panels (which options exist) and spec_loader (config + parsing + display for them)
  • Today both resolve to specs/annotation_library.json plus a thin per-genome document (human_grch38, human_grch37)
  • Everything downstream already works off the assembled document, so swapping the source is a change to those two reads — not to the interpreters
  • The frontend never reads a spec: it only ever sees what the backend serves

Outside contacts

  • Genome metadata / search — species lookup for the selector, and the gff/fasta paths for a run
  • Seqera / Nextflow — launch and poll (prod). In dev this is a manual HPC run and a hand-placed VCF
  • Plugin data on /nfs — read by VEP itself, named by the config the backend emits
  • Link-outs — ClinVar, AmiGO, OpenTargets, MaveDB, ProtVar, opened from the results panel
